#### Table 1: The `if-else if-else` Structure

| Component | Purpose | When It Runs |
| :--- | :--- | :--- |
| **`if`** | The first condition check. | Runs if the condition is `true`. If `false`, moves to the next `else if`. |
| **`else if`** | Additional condition checks (can have **any number**). | Runs if **all previous conditions were `false`** AND **this condition is `true`**. |
| **`else`** | The catch-all fallback (optional). | Runs if **all** previous conditions were `false`. |

**Key rule:** The chain stops at the **first** condition that evaluates to `true`. Once a block executes, the entire `if-else if-else` structure is skipped.

#### The "Else is Optional" Rule (As Mentioned in Your Lesson)

When you omit the `else`, it simply means **"do nothing if none of the conditions match"**.

```csharp
int temperature = 25;

if (temperature > 30)
{
    Console.WriteLine("It's hot outside!");
}
else if (temperature < 10)
{
    Console.WriteLine("It's cold outside!");
}
// No else! If temperature is between 10 and 30, nothing prints.
```

**Execution flow:**
- If `temperature` is 35 → prints "It's hot outside!"
- If `temperature` is 5 → prints "It's cold outside!"
- If `temperature` is 25 → **nothing prints** (the chain ends quietly).



####  Critical Nuances & Best Practices

| Concept | Explanation | Example |
| :--- | :--- | :--- |
| **Order Matters!** | Conditions are evaluated from top to bottom. Put the **most specific** conditions first. | ❌ `if (score >= 60)` first would catch all scores ≥60, so `else if (score >= 90)` would never run. ✅ Put `>= 90` first. |
| **Mutually Exclusive** | Only one branch ever runs (the first `true` condition). The rest are skipped. | Once `score >= 80` is true, it **does not** check `score >= 70` at all. |
| **Redundant Conditions** | You don't need to repeat the previous condition—it's already implied. | Instead of `else if (score < 90 && score >= 80)`, simply write `else if (score >= 80)`. |
| **Limit the Chain Length** | Long chains become hard to read. Consider `switch` or a dictionary lookup for many conditions. | If you have 10+ `else if` blocks, refactor! |

####  When to Use `else if` vs `switch`

| Scenario | Recommended Approach | Why |
| :--- | :--- | :--- |
| **Testing ranges** (e.g., `score >= 90`, `score >= 80`) | `if-else if` | `switch` doesn't support range checks well (without C# 9.0's relational patterns). |
| **Testing a single variable against many exact values** (e.g., `day == "Monday"`) | `switch` | Cleaner, more readable, and the compiler warns you if you miss a case. |
| **Complex conditions** (e.g., `age > 18 && country == "US"`) | `if-else if` | `switch` is limited to constant values. |
| **Long chains (10+ conditions)** | Refactor to a `Dictionary` or use pattern matching | Maintainability becomes a nightmare—consider a design pattern like Strategy. |
