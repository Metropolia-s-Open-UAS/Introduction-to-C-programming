#### If-else statement
- If-else differs from the If-statement only by the alternative else statement, which is executed always if the Boolean expression in the if statement is false. In the following example, the output of the program is “False”.

- It's clear that the condition can not be simultaneously true and false so either the if-statement or the else-statement can be run. After the if-else statement the next statements in order are run. In this case there are no other statements to be run as the Main method ends.

#### Table 1: `if` vs `if-else` – The Behavior Difference

| Scenario | What Happens | When to Use |
| :--- | :--- | :--- |
| **`if` alone** | The `if` block runs on `true`. On `false`, the program **skips** the entire `if` block and continues with subsequent code. | When you only need to take action in one specific case. |
| **`if-else`** | The `if` block runs on `true`. The `else` block runs on `false`. **Exactly one** of the two blocks will always execute. | When you need to handle both possible outcomes of a condition. |



####  Execution Flow (Step-by-Step)

```csharp
bool condition = false;            // Step 1: Set condition to false

if (condition)                     // Step 2: Evaluate condition (false)
{
    Console.WriteLine("True");     // Step 3: SKIPPED (condition is false)
}
else
{
    Console.WriteLine("False");    // Step 4: RUNS (because else handles false)
}

// Step 5: Program continues here (Main method ends)
```

**Key insight:** Since a Boolean expression can only be `true` or `false`, **exactly one** of the two branches is executed. There's no third option.



#### 💻 Real-World Example – Age Verification

```csharp
int age = 16;

if (age >= 18)
{
    Console.WriteLine("You are old enough to vote.");
}
else
{
    Console.WriteLine("You are too young to vote.");
}

// Output: "You are too young to vote."
```



####  Critical Insights for Your Code

| Concept | Explanation | Good Practice |
| :--- | :--- | :--- |
| **Exactly one branch runs** | Either the `if` block **or** the `else` block executes. Never both, never neither. | This is guaranteed by Boolean logic—a condition must be either `true` or `false`. |
| **`else` is optional** | You can have an `if` without an `else`, but you cannot have an `else` without an `if`. | `else` only makes sense as the fallback to an `if` condition. |
| **Braces `{ }` are optional but recommended** | For single statements, you can omit braces, but it's a common source of bugs. | Always use braces to avoid confusion and make your code maintainable. |
| **`else` can be nested** | You can put `if` statements inside `else` blocks (which is exactly what `else if` does). | Use `else if` for cleaner code when checking multiple conditions. |

####  Common Beginner Mistakes

| ❌ Bad Code | ✅ Good Code | Why |
| :--- | :--- | :--- |
| `if (x = 5) { ... }` | `if (x == 5) { ... }` | `=` is assignment, `==` is equality. The first compiles but is always `true`! |
| `if (age >= 18); { Console.WriteLine("Adult"); }` | `if (age >= 18) { Console.WriteLine("Adult"); }` | The semicolon after the `if` ends the condition, so the block runs **regardless** of the condition! (This is a very sneaky bug!) |
| `if (x > 0)` <br> `Console.WriteLine("Positive");` <br> `Console.WriteLine("Greater than zero");` | `if (x > 0) { Console.WriteLine("Positive"); }` <br> `Console.WriteLine("Greater than zero");` | Without braces, **only the first line** is part of the `if`. The second line always runs. |
