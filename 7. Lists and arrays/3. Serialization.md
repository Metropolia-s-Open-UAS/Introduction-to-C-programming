#### Serialization
- The List class is a powerful tool for data manipulation. However, sometimes we need to save the runtime data for later use or for some other application to handle. The process called serialization enables us to save the state of an object to a memory location, a database or a file. Once we need to recreate the objects we call the reverse process, known as deserialization.

- The serialization process can be handled in various ways and formats. JSON serialization (System.Text.Json namespace) is based on the JSON open standard and produces serialization in JSON format. Binary serialization uses binary encoding to produce files for storage media or socket-based network streams. XML serialization serializes the object data according to a specific XML Schema definition language document. The following example shows object serialization in XML format.

- The program produces output.xml file which has the following contents:
```xml
<?xml version="1.0" encoding="utf-8"?>
<ArrayOfCountry xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xmlns:xsd="http://www.w3.org/2001/XMLSchema">
  <Country>
    <Name>Finland</Name>
  </Country>
  <Country>
    <Name>Sweden</Name>
  </Country>
</ArrayOfCountry>
```

####  Serialization – Overview

| Term | Description |
| :--- | :--- |
| **Serialization** | The process of converting an object's state into a format that can be stored or transmitted (e.g., JSON, XML, binary). |
| **Deserialization** | The reverse process—reconstructing an object from the serialized format. |
| **Purpose** | Save data between program runs, send data over networks, share data between different systems. |
| **Common Formats** | JSON, XML, Binary, YAML, etc. |

#### Table 1: Common Serialization Formats

| Format | Namespace | Best For | Characteristics |
| :--- | :--- | :--- | :--- |
| **JSON** | `System.Text.Json` or `Newtonsoft.Json` | Web APIs, configuration files, data exchange | Human-readable, lightweight, widely supported |
| **XML** | `System.Xml.Serialization` | Legacy systems, configuration files | Human-readable, verbose, supports schemas |
| **Binary** | `System.Runtime.Serialization.Formatters.Binary` | High-performance storage, .NET-to-.NET communication | Not human-readable, efficient, .NET-specific |
| **YAML** | `YamlDotNet` (third-party) | Configuration files | Human-readable, cleaner than JSON/XML |

#### JSON Serialization (Modern Standard)

**JSON** is the most common serialization format today. Here's how to use it:

```csharp
using System;
using System.Collections.Generic;
using System.Text.Json;

// Define the class (must be public)
public class Country
{
    public string Name { get; set; }
}

class Program
{
    static void Main()
    {
        // Create a list of countries
        List<Country> countries = new List<Country>
        {
            new Country { Name = "Finland" },
            new Country { Name = "Sweden" }
        };

        // Serialize to JSON
        string jsonString = JsonSerializer.Serialize(countries);
        Console.WriteLine("Serialized JSON:");
        Console.WriteLine(jsonString);

        // Save to file
        File.WriteAllText("countries.json", jsonString);

        // Deserialize from JSON
        string jsonFromFile = File.ReadAllText("countries.json");
        List<Country> deserializedCountries = JsonSerializer.Deserialize<List<Country>>(jsonFromFile);

        // Verify
        foreach (var country in deserializedCountries)
        {
            Console.WriteLine($"Country: {country.Name}");
        }
    }
}
```

**Output (countries.json):**
```json
[
  {"Name":"Finland"},
  {"Name":"Sweden"}
]
```

#### XML Serialization (Your Example)

Here's the complete code that produces the XML shown in your example:

```csharp
using System;
using System.Collections.Generic;
using System.IO;
using System.Xml.Serialization;

// Class must be public and have a parameterless constructor
[Serializable]
public class Country
{
    public string Name { get; set; }
}

class Program
{
    static void Main()
    {
        // Create a list of countries
        List<Country> countries = new List<Country>
        {
            new Country { Name = "Finland" },
            new Country { Name = "Sweden" }
        };

        // XML Serialization
        XmlSerializer serializer = new XmlSerializer(typeof(List<Country>));
        using (StreamWriter writer = new StreamWriter("output.xml"))
        {
            serializer.Serialize(writer, countries);
        }

        Console.WriteLine("XML file created: output.xml");

        // Deserialize from XML
        using (StreamReader reader = new StreamReader("output.xml"))
        {
            List<Country> deserializedCountries = (List<Country>)serializer.Deserialize(reader);
            foreach (var country in deserializedCountries)
            {
                Console.WriteLine($"Deserialized: {country.Name}");
            }
        }
    }
}
```

**Output (output.xml):**
```xml
<?xml version="1.0" encoding="utf-8"?>
<ArrayOfCountry xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xmlns:xsd="http://www.w3.org/2001/XMLSchema">
  <Country>
    <Name>Finland</Name>
  </Country>
  <Country>
    <Name>Sweden</Name>
  </Country>
</ArrayOfCountry>
```

#### Table 2: Important Serialization Rules

| Rule | Explanation | Example |
| :--- | :--- | :--- |
| **Public Properties/Fields Only** | Only public members are serialized. Private fields are ignored. | `public string Name { get; set; }` ✅ <br> `private int id;` ❌ (ignored) |
| **Parameterless Constructor** | The class must have a parameterless constructor for deserialization. | `public Country() { }` ✅ |
| **`[Serializable]` Attribute** | Marks a class as serializable (required for binary serialization; optional for JSON/XML). | `[Serializable]` <br> `public class Country` |
| **Non-Serialized Fields** | Use `[NonSerialized]` to exclude specific fields. | `[NonSerialized]` <br> `private int tempCache;` |
| **Nested Objects** | Serializes nested objects automatically. | `public List<City> Cities { get; set; }` |

#### Binary Serialization (Memory/File/Network)

Binary serialization is the most efficient but **not human-readable**:

```csharp
using System;
using System.Collections.Generic;
using System.IO;
using System.Runtime.Serialization.Formatters.Binary;

[Serializable]
public class Country
{
    public string Name { get; set; }
}

class Program
{
    static void Main()
    {
        List<Country> countries = new List<Country>
        {
            new Country { Name = "Finland" },
            new Country { Name = "Sweden" }
        };

        // Binary Serialization
        BinaryFormatter formatter = new BinaryFormatter();
        using (FileStream stream = new FileStream("countries.bin", FileMode.Create))
        {
            formatter.Serialize(stream, countries);
        }

        // Binary Deserialization
        using (FileStream stream = new FileStream("countries.bin", FileMode.Open))
        {
            List<Country> deserialized = (List<Country>)formatter.Deserialize(stream);
            foreach (var country in deserialized)
            {
                Console.WriteLine($"Country: {country.Name}");
            }
        }
    }
}
```

#### Controlling Serialization with Attributes

```csharp
using System;
using System.Xml.Serialization;

[Serializable]
public class Person
{
    // Will be serialized
    public string Name { get; set; }
    
    // Will be serialized with a different name
    [XmlElement("AgeInYears")]
    public int Age { get; set; }
    
    // Will be serialized as an attribute
    [XmlAttribute]
    public int Id { get; set; }
    
    // Will NOT be serialized
    [NonSerialized]
    private string tempPassword;
    
    // Will NOT be serialized
    [XmlIgnore]
    public bool IsActive { get; set; }
}
```

**Serialized XML:**
```xml
<Person Id="1">
  <Name>John Doe</Name>
  <AgeInYears>30</AgeInYears>
</Person>
```

#### JSON Serialization Options

```csharp
using System.Text.Json;

// Pretty print JSON
var options = new JsonSerializerOptions
{
    WriteIndented = true
};
string json = JsonSerializer.Serialize(countries, options);

// Ignore null values
options.DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull;

// Use camelCase (standard for web APIs)
options.PropertyNamingPolicy = JsonNamingPolicy.CamelCase;
```

**Output with `WriteIndented: true`:**
```json
[
  {
    "name": "Finland"
  },
  {
    "name": "Sweden"
  }
]
```

#### Common Mistakes & Best Practices

|  Bad Code |  Good Code | Why |
| :--- | :--- | :--- |
| `private string Name { get; set; }` | `public string Name { get; set; }` | Private members are not serialized by default. |
| `class Person { public Person(string name) { } }` | `class Person { public Person() { } public Person(string name) { } }` | Missing parameterless constructor causes deserialization errors. |
| Using BinaryFormatter in modern apps | Use JSON or `System.Text.Json` | BinaryFormatter is deprecated for security reasons. |
| Hardcoding file paths | Use `Path.Combine(AppDomain.CurrentDomain.BaseDirectory, "data.json")` | Ensures file paths work correctly. |

#### Challenge to Test Your Understanding

> **What will be serialized and what will be ignored?**

```csharp
[Serializable]
public class Student
{
    public string Name { get; set; }
    private int age;
    public int StudentId { get; set; }
    [NonSerialized]
    public string TempData;
    public Student() { }
    public Student(string name) { Name = name; }
}
```

<details>
<summary>Click to reveal the answer</summary>

**Serialized:**
- `Name` ✅ (public)
- `StudentId` ✅ (public)

**Ignored:**
- `age` ❌ (private)
- `TempData` ❌ (`[NonSerialized]` attribute)

**Why:** Only public fields/properties are serialized by default. Private fields are ignored, and `[NonSerialized]` explicitly excludes the field.

</details>

#### Summary: The Golden Rules

| Rule | Explanation |
| :--- | :--- |
| **Use public properties** | Only public members are serialized by default. |
| **Include a parameterless constructor** | Required for deserialization. |
| **Use `[NonSerialized]` or `[JsonIgnore]`** | To exclude sensitive or unnecessary fields. |
| **Choose the right format** | JSON for web/modern apps, XML for legacy systems, Binary for .NET-only high-performance. |
| **Handle exceptions** | Always use `try-catch` when reading/writing files. |
