#### Jump Statments
1.**Goto** : The goto statement transfers control to the specified label. It can be used for example to transfer control to a another switch-case label or to any other part of the code, possibly to avoid deeply nested loops or other program structures.
2.**Break** :  The break statement ends the execution of the current loop or switch statement before any condition evaluation is made. The control will return to the statement following the terminated statement.
3.**Continue**: The continue statement forces the control flow to continue from the next loop iteration, skipping any code in between.
4.**Return**:  The return statement is used to terminate the execution of the method and return the control to the calling method. If the statement is inside a try block, the finally block (if available) will be executed before returning control.

#### Table 1: Jump Statements – At a Glance

| Statement | Primary Purpose | When to Use | When to Avoid |
| :--- | :--- | :--- | :--- |
| **`goto`** | Transfers control to a labeled statement. | Breaking out of deeply nested loops (rare), or within `switch` to jump to another case. | Almost always—it creates "spaghetti code" that's hard to read/debug. |
| **`break`** | Exits the current loop or `switch` immediately. | Ending a loop early when a condition is met. | Rarely avoided—`break` is perfectly acceptable! |
| **`continue`** | Skips to the next iteration of the loop. | Skipping certain elements in a loop (e.g., odd numbers). | When you need to execute the remaining code in the loop. |
| **`return`** | Exits the current method and returns control to the caller. | When a method has completed its work and should exit. | When you still need to execute code after the `return` (use `finally` instead). |
| **`throw`** | Throws an exception, transferring control to the nearest matching `catch` block. | When an error condition occurs (e.g., invalid input). | When you want to handle the error locally instead of propagating it. |

#### Table 2: Detailed Breakdown of Each Jump Statement

| Statement | Syntax | Description | Example |
| :--- | :--- | :--- | :--- |
| **`goto`** | `goto label;` <br> `label: // code` | Transfers control to a labeled statement. Can jump forward or backward. | `goto End;` <br> `End: Console.WriteLine("Done");` |
| **`break`** | `break;` | Immediately exits the innermost loop or `switch` statement. | `if (i == 5) break;` |
| **`continue`** | `continue;` | Skips the rest of the current loop iteration and moves to the next iteration. | `if (i % 2 == 0) continue;` |
| **`return`** | `return;` (void) <br> `return value;` (non-void) | Exits the method and optionally returns a value. | `return;` or `return sum;` |
| **`throw`** | `throw new Exception("Message");` | Throws an exception. Can also rethrow using `throw;` inside a `catch` block. | `throw new ArgumentException("Invalid input");` |


#### `goto` Statement – When It's Used (And When It Shouldn't Be)

The `goto` statement is the **most controversial** jump statement. While it's available in C#, **modern best practices strongly discourage its use** except in specific scenarios.

#### Why Avoid `goto`?

| Reason | Explanation |
| :--- | :--- |
| **Readability** | Makes code harder to follow—"spaghetti code." |
| **Debugging** | Control flow jumps unpredictably, making debugging difficult. |
| **Maintainability** | Future developers will struggle to understand the logic. |
| **Alternatives** | `break`, `continue`, and `return` handle almost all use cases cleanly. |

#### Legitimate Uses of `goto` (Rare)

| Scenario | Example |
| :--- | :--- |
| **Jumping to another `switch` case** | `goto case 3;` |
| **Breaking out of deeply nested loops** | Instead of setting a flag, jump directly to the exit label. |

**Example of `goto` in `switch`:**
```csharp
int day = 2;

switch (day)
{
    case 1:
        Console.WriteLine("Monday");
        break;
    case 2:
        Console.WriteLine("Tuesday");
        goto case 3; // Jump to case 3
    case 3:
        Console.WriteLine("Wednesday");
        break;
    default:
        Console.WriteLine("Invalid");
        break;
}
```
**Output:** `Tuesday` `Wednesday`


#### `break` Statement – The Safe Exit

`break` is the **most commonly used** jump statement. It's safe, clear, and widely accepted.

```csharp
for (int i = 0; i < 10; i++)
{
    if (i == 5)
    {
        Console.WriteLine("Breaking at 5!");
        break; // Exit the loop immediately
    }
    Console.WriteLine(i);
}
// Output: 0, 1, 2, 3, 4, "Breaking at 5!"
```

**When to use `break`:**
- Exiting a loop when a condition is met.
- Exiting a `switch` case.
- Preventing infinite loops.

**When NOT to use `break`:**
- When you need the loop to naturally exit (e.g., when the condition becomes `false`).

#### `continue` Statement – Skip the Rest

`continue` skips the remaining code in the current iteration and jumps to the **condition check** (or the next iteration in `foreach`).

```csharp
for (int i = 0; i < 5; i++)
{
    if (i % 2 == 0)
    {
        continue; // Skip even numbers
    }
    Console.WriteLine(i);
}
// Output: 1, 3
```

**When to use `continue`:**
- Skipping invalid or irrelevant elements.
- Simplifying complex conditions (avoid deeply nested `if` statements).

#### `return` Statement – The Final Exit

`return` exits the method immediately, **regardless** of where you are in the code.

```csharp
static int AddNumbers(int a, int b)
{
    return a + b; // Returns the sum and exits the method
}
```

**When to use `return`:**
- When a method has completed its logic.
- As an "early exit" for validation (fail-fast pattern).

```csharp
static void ValidateAge(int age)
{
    if (age < 0 || age > 120)
    {
        Console.WriteLine("Invalid age!");
        return; // Exit early
    }
    Console.WriteLine($"Age is valid: {age}");
}
```

#### `throw` Statement – Exception Handling

`throw` is used to raise an exception, transferring control to the nearest matching `catch` block.

```csharp
static int Divide(int a, int b)
{
    if (b == 0)
    {
        throw new DivideByZeroException("Cannot divide by zero!");
    }
    return a / b;
}
```

**When to use `throw`:**
- When an error condition occurs that cannot be handled locally.
- To propagate errors up the call stack.

#### Comparison Table: When to Use Each Jump Statement

| Scenario | Best Choice | Why |
| :--- | :--- | :--- |
| **Exit a loop early** | `break` | Clean and clear. |
| **Skip to the next iteration** | `continue` | Standard practice for skipping elements. |
| **Exit a method** | `return` | The only correct way to exit a method. |
| **Handle an error condition** | `throw` | Proper exception handling. |
| **Jump to a labeled statement** | `goto` (rarely) | Almost never needed. Use `break`, `continue`, or restructure code instead. |
| **Switch to another `case`** | `goto case` | One of the few acceptable uses of `goto`. |

#### Nested Loops and Jump Statements

In nested loops, jump statements affect the **innermost loop**:

```csharp
for (int i = 0; i < 3; i++)
{
    Console.WriteLine($"Outer: {i}");
    for (int j = 0; j < 3; j++)
    {
        if (j == 1)
        {
            break; // Exits ONLY the inner loop
        }
        Console.WriteLine($"  Inner: {j}");
    }
}
```
**Output:**
```
Outer: 0
  Inner: 0
Outer: 1
  Inner: 0
Outer: 2
  Inner: 0
```

**To break out of multiple loops:** Use a flag variable or `goto`:

```csharp
bool exit = false;
for (int i = 0; i < 10 && !exit; i++)
{
    for (int j = 0; j < 10; j++)
    {
        if (j == 5)
        {
            exit = true;
            break; // Exits inner loop, outer loop stops because condition is false
        }
    }
}
```

#### Common Mistakes & Best Practices

|  Bad Code |  Good Code | Why |
| :--- | :--- | :--- |
| `goto End;` <br> `// ... lots of code ...` <br> `End: Console.WriteLine("Done");` | Restructure code using `break` or `return`. | `goto` makes code unpredictable and hard to maintain. |
| `return` inside a `finally` block | Avoid returning from `finally`. | It can suppress exceptions or mask errors. |
| `throw;` (empty) outside a `catch` block | Only use `throw;` inside a `catch` block to rethrow the current exception. | Using `throw;` outside `catch` causes a compile-time error. |
| **Unreachable code** after `return` or `throw` | Ensure all code is reachable or remove it. | `return` and `throw` exit the method immediately, so code after them never runs. |

#### Connecting to Your Previous Programs

Here's a complete example using multiple jump statements:

```csharp
static void Main(string[] args)
{
    // Use return to exit early if no arguments
    if (args.Length == 0)
    {
        Console.WriteLine("No arguments provided.");
        return; // Exit the program
    }

    // Use foreach with break to stop early
    foreach (string arg in args)
    {
        if (arg == "--help")
        {
            Console.WriteLine("Usage: Program.exe <name>");
            break; // Stop looping
        }
    }

    // Use continue inside a for loop to skip empty strings
    for (int i = 0; i < args.Length; i++)
    {
        if (string.IsNullOrEmpty(args[i]))
        {
            continue;
        }
        Console.WriteLine($"Argument {i + 1}: {args[i]}");
    }
}
```

#### Summary: The Golden Rules

| Jump Statement | Golden Rule |
| :--- | :--- |
| **`goto`** | **Avoid it.** There is almost always a better way. |
| **`break`** | **Use it freely** to exit loops and `switch` cases. |
| **`continue`** | **Use it freely** to skip to the next iteration. |
| **`return`** | **Use it freely** to exit methods. Always ensure `finally` blocks execute. |
| **`throw`** | **Use it** for error conditions. Always handle exceptions appropriately. |

1. **`break`** and **`continue`** are your friends for loop control.
2. **`return`** is essential for method exits.
3. **`throw`** is for exception handling.
4. **`goto`** is almost always a bad idea—avoid it unless you have a specific, justified use case.
