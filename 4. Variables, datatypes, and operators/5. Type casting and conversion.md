#### Type casting and conversion
- `C#` language is a **statically typed programming language**. That means every variable’s type is known at **compile-time** (instead of **run-time**) and cannot be changed. However, it is possible to have a copy of a `variable` or `method` parameter of another type. This operation is called `type conversion`.
-  There are different kinds of conversions: `implicit` conversions, `explicit` conversions, `user-defined` conversions and conversions with `helper classes`.
-  Commonly used conversions include `implicit` and `explicit` conversions. `Implicit` conversion requires no `special syntax` and no `data` will be lost in the process.
  >  or example, converting a `small int` can be converted to `larger int` types. `Explicit` conversions instead require a `cast expression` and information can be lost in the process. For example, numeric conversions with different range or precision may cause information loss.
```csharp
short a = 122;
long b = a; // implicit conversion, b=122
float y = 2.189F;
int x = (int) y;  // explicit conversion (cast), x=2
```

| Conversion Type | Description | Who defines it? | Syntax | Example |
| :--- | :--- | :--- | :--- | :--- |
| **Implicit Conversion** | No special syntax needed. **Safe**—guaranteed no data loss (magnitude-wise) and no exceptions. | Built into the language (predefined) or user-defined via `implicit` keyword. | Automatic | `int i = 10; long l = i;` |
| **Explicit Conversion** | Requires a **cast** expression `(type)`. **Potentially unsafe**—can lose data or throw exceptions (overflow). | Built-in or user-defined via `explicit` keyword. | `(targetType)value` | `double d = 3.9; int i = (int)d;` (i becomes 3, truncates) |
| **User-Defined Conversion** | You define how your `struct` or `class` converts to/from another type. | Defined by the developer using `implicit` or `explicit` operators. | Custom syntax | `public static implicit operator int(MyClass c) { return c.Value; }` |
| **Conversion with Helper Classes** | Using .NET's built-in utility classes to convert between unrelated types (e.g., `string` to `int`, or any type to `string`). | Provided by the .NET framework. | `Convert.ToInt32()`, `.Parse()`, `.TryParse()` | `int x = Convert.ToInt32("123");` |


### Table 2: Implicit vs. Explicit Numeric Conversions (The Golden Rule)

The "safety" rule for numeric types is: **Implicit = widening** (smaller bucket → bigger bucket). **Explicit = narrowing** (bigger bucket → smaller bucket, requires a cast).

| Conversion Direction | Safety | Syntax Required | Potential Issues |
| :--- | :--- | :--- | :--- |
| `int` → `long` | ✅ Safe | *Implicit* (automatic) | None. You can always fit a 32-bit number into a 64-bit bucket. |
| `int` → `double` | ✅ Safe (mostly) | *Implicit* (automatic) | ⚠️ `int` (exact) to `double` (approximate) *can* lose **precision** for very large numbers (>2^53), but never magnitude. It won't throw. |
| `double` → `int` | ⚠️ Unsafe | *Explicit* (cast required) | **Truncation** (`.9` becomes `0`). Data loss. Possible `OverflowException` if the double is too huge. |
| `long` → `int` | ⚠️ Unsafe | *Explicit* (cast required) | **Overflow**. If the `long` > 2.1B, it wraps around (e.g., becomes negative) unless you use `checked`. |
| `float` → `double` | ✅ Safe | *Implicit* | No real issues. |
| `double` → `float` | ⚠️ Unsafe | *Explicit* | Loss of precision (rounding). |


Since `Console.ReadLine()` always returns a `string`, you need these *every time* you read numbers from the user:

| Method | Example | Behavior on Failure | When to use |
| :--- | :--- | :--- | :--- |
| **`Convert.ToInt32()`** | `int x = Convert.ToInt32("123");` | Throws `FormatException` if input is invalid. | When you are **sure** the input is valid and want an exception on failure. |
| **`int.Parse()`** | `int x = int.Parse("123");` | Throws `FormatException` if invalid. | Same as `Convert`, but more direct for specific types. |
| **`int.TryParse()`** | `bool success = int.TryParse("123", out int x);` | **Returns `false`** instead of throwing. Does not crash. | **The safest choice**—preferred for user input where bad data is expected. |
| **`.ToString()`** | `string s = 123.ToString();` | Always works. | Converting *anything* to a string. |

**Key difference between `Convert` and `Parse`:**  
- `Convert.ToInt32(null)` returns `0` (handles null gracefully).  
- `int.Parse(null)` throws an `ArgumentNullException`.  
*(This is a common interview question!)*


###  Table 4: Casting vs. Conversion (It's NOT the same!)

Many beginners think "casting" and "converting" are synonyms. They are **not**:

| Aspect | Explicit Cast (e.g., `(int)myDouble`) | Helper Conversion (e.g., `Convert.ToInt32()`) |
| :--- | :--- | :--- |
| **Behavior on overflow** | Wraps around (in `unchecked` context) or throws (in `checked`). | Throws `OverflowException` (always safe). |
| **Behavior on rounding** | **Truncates** toward zero (e.g., 2.9 → 2, -2.9 → -2). | **Rounds** to the nearest integer (banker's rounding for midpoint). |
| **Behavior on strings** | Doesn't work. You cannot write `(int)"123"`. | Works perfectly. |
| **Performance** | Extremely fast (compiler-level). | Slightly slower (method call overhead). |
