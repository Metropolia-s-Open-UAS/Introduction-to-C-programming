#### Declaring variables and arrays
- The syntax for declaring a variable is:
```csharp
type variableName;

```
- The syntax for declaring an array is:
```csharp
type[] myArray = new type[size];

```
- The syntax for the declaration and initialization of a variable:
```csharp
type variableName = value;
```
- The syntax for the declaration and initialization of an array:
```csharp
type[] myArray = new type[] { value1, value2, .., valueN };
type[] myArray = { value1, value2, .., valueN }; // implicitly typed array
```
> Examples
> 
> 1. int myVar; // declaration
> 
> 2. int myVar = 5; //declaration with assignment
> 
> 3. int[] myArray; // declaration – later must use new keyword when assigning values
> 
> 4. int[] myArray = new int[] {1, 2, 3, 5, 6}; // declaration with assignment
> 
> 5. int[] myArray = {1, 2, 3, 4, 5}; // declaration and assignment (implicitly typed)


#### Table 1: Syntax Patterns for Variables & Arrays

| Action | Syntax Pattern | When to use it |
| :--- | :--- | :--- |
| **Declare a variable** | `type variableName;` | When you know the variable name and type, but don't have a value yet (e.g., to store user input later). |
| **Declare + Initialize a variable** | `type variableName = value;` | When you know the starting value immediately. Always preferred to avoid uninitialized variables. |
| **Declare an array variable** | `type[] myArray;` | Just reserves the reference. **No memory allocated yet**—must use `new` before assigning values. |
| **Declare + Instantiate (fixed size)** | `type[] myArray = new type[size];` | Creates an array with empty/default slots. All elements get default values (`0` for numbers, `false` for bool). |
| **Declare + Init with values (Explicit)** | `type[] myArray = new type[] { v1, v2, ... };` | Creates an array of the exact length based on how many values you provide. |
| **Declare + Init (Shorthand)** | `type[] myArray = { v1, v2, ... };` | Same as above, but omits `new type[]`. Compiler infers it. **(Not implicitly typed!)** |
| **Truly Implicitly Typed Array** | `var myArray = new[] { v1, v2, ... };` | Compiler figures out the type from the values. Saves typing when the type is obvious. |



| Your Code | Correct Terminology | Memory Behavior |
| :--- | :--- | :--- |
| `int myVar;` | Variable Declaration | Memory is reserved on the Stack, but contains **garbage data** until assigned. (Cannot use it before assigning!) |
| `int myVar = 5;` | Declaration with Initialization | Memory reserved AND filled with `5`. Ready to use immediately. |
| `int[] myArray;` | Array Variable Declaration | Only a reference (null) is created on the Stack. **No array exists on the Heap yet.** |
| `int[] myArray = new int[] {1, 2, 3, 5, 6};` | Explicit Array Creation & Initialization | Allocates Heap memory for 5 integers, copies the values in. |
| `int[] myArray = {1, 2, 3, 4, 5};` | Array Initializer (Shorthand) | Same as above. The compiler translates this behind the scenes to `new int[] { ... }`. |



| What you wrote | Official Name | Explanation |
| :--- | :--- | :--- |
| `int[] myArray = {1, 2, 3};` | **Array Initializer** (using implicit typing *only* for the creation expression) | The variable type is **explicitly** declared as `int[]`. The shorthand just saves you from typing `new int[]`. |
| `var myArray = new[] {1, 2, 3};` | **Implicitly Typed Array** | The variable type is `var` (compiler figures out it's `int[]`), AND the creation uses `new[]`. This is the *true* implicit array. |

**Why does this matter?** If you use `var myArray = new[] { 1, 2.5, 3 };`, the compiler will throw an error because it can't figure out if you want `int[]`, `double[]`, or `float[]`. You must ensure all values have the same type (or use `new double[]` explicitly).

| Rule | Explanation |
| :--- | :--- |
| **Default Values** | When you do `int[] myArray = new int[5];`, the array is filled with **default values**: `0` for numbers, `false` for bool, `null` for reference types. You don't get garbage data like in C/C++! |
| **The `new` Keyword** | For arrays (which are Reference Types), `new` allocates memory on the **Heap**. If you just write `int[] myArray;` and try to access `myArray[0]`, you get a **NullReferenceException** because it points to nothing! |
| **Fixed Length** | Arrays in C# have a **fixed length**. Once you declare `new int[5]`, you cannot add a 6th element without creating a new, larger array. (Later, you'll learn `List<T>` for dynamic sizes). |
| **Counting Elements** | Use `myArray.Length` to get the number of elements. Since arrays are zero-indexed, the last index is always `myArray.Length - 1`. |


```csharp
int[] arr1;                  // arr1 is null (no memory)
arr1 = new int[3];           // Now arr1 holds [0, 0, 0] (default values)

int[] arr2 = new int[] { 10, 20, 30 }; // Explicit
int[] arr3 = { 10, 20, 30 };           // Shorthand (works only during declaration)
var arr4 = new[] { 10, 20, 30 };       // True implicit typing (arr4 is int[])

arr3[0] = 999;               // arr3 is now [999, 20, 30]
// arr3[3] = 50;             // ERROR! Index was outside the bounds of the array.
```
