#### Naming variables
- Variable names must follow the following rules and characteristics:
   - Variable names must be unique
   - The name can contain letters, digits and underscore character
   - First character must be a letter (underscore is acceptable)
   - Variable name is not a reserved keyword like `static`, `double`, function etc.
   - Variables are case sensitive
> Examples of legal and illegal variable names, In general, variable names should be descriptive and following the same naming conventions.

| Rule | Explanation | Valid Example | Invalid Example |
| :--- | :--- | :--- | :--- |
| **Must be unique within scope** | You cannot have two variables with the exact same name in the same method or block. | `int age;` and later `string name;` (fine). | `int age; string age;` (error). |
| **Can contain letters, digits, underscores** | Alphanumeric and underscore only. No spaces, hyphens, or special characters like `#`, `$`, `@` (except `@` as a prefix escape). | `myVar_1`, `count2`, `_private` | `my-var`, `total$`, `first name` |
| **First character must be a letter or underscore** | Cannot start with a digit. | `_count`, `myVariable` | `1stPlace` |
| **Cannot be a reserved keyword** | Keywords like `class`, `int`, `static`, `double`, `void`, `if`, `for` are forbidden. | `@class` *(legal escape, but avoid!)* | `int` (you can't name a variable `int`). |
| **Case-sensitive** | `myVar` and `MyVar` are two completely different variables. | `int myVar = 5; int MyVar = 10;` (both compile). | (Not applicable—this is a rule, not an example). |


| Variable | Legal? | Why? |
| :--- | :--- | :--- |
| `variable123` | ✅ **Legal** | Starts with a letter, contains only letters and digits. Perfectly valid. |
| `1hundred` | ❌ **Illegal** | Starts with a digit. Change to `oneHundred` or `hundred1`. |
| `fixed` | ❌ **Illegal** | `fixed` is a reserved keyword in C# (used for pointers in unsafe code). You could escape it as `@fixed` but **don't**—just rename it! |
| `myVariable` | ✅ **Legal** | Standard camelCase. Perfectly valid. |
| `Row_count` | ✅ **Legal** | Starts with a letter, contains underscore. Valid, but this naming style is unusual in C# (snake_case is more common in Python). |



| Category | Naming Style | Example | Reasoning |
| :--- | :--- | :--- | :--- |
| **Local Variables** | **camelCase** (starts lowercase, subsequent words capitalized) | `int myAge;` <br> `string firstName;` <br> `bool isLoggedIn;` | This is the default for variables inside methods. |
| **Method Parameters** | **camelCase** | `void PrintName(string userName)` | Same as local variables. |
| **Private Fields** | **\_camelCase** (underscore prefix + camelCase) | `private int _age;` <br> `private string _name;` | The underscore clearly distinguishes fields from local variables. *(Note: Some teams omit the underscore and just use camelCase, but the underscore is very common in .NET Core/ASP.NET codebases).* |
| **Public Fields / Properties** | **PascalCase** (starts uppercase, subsequent words capitalized) | `public int Age { get; set; }` <br> `public string FirstName;` | Properties and public members scream "I am accessible from outside!" via uppercase. |
| **Class Names** | **PascalCase** | `class CustomerManager` | Classes, structs, and interfaces use PascalCase. |
| **Interface Names** | **I** + **PascalCase** (starts with capital I) | `interface IRepository` | The "I" prefix is a universal standard to distinguish interfaces from classes. |
| **Constants** | **UPPER_SNAKE_CASE** (legacy) OR **PascalCase** (modern) | `const int MAX_RETRIES = 3;` (old school) <br> `const int MaxRetries = 3;` (modern .NET Core style) | Microsoft has shifted toward PascalCase even for constants in recent years, but both are seen. |


| Bad Practice | Why it's bad | Better Alternative |
| :--- | :--- | :--- |
| `int a;` | Completely meaningless. No one knows what `a` stands for. | `int age;` or `int index;` |
| `string strName;` | **Hungarian Notation** (prefixing with type). It was popular in older C/C++ but is **discouraged** in C# because IDEs show you the type anyway. | `string name;` |
| `string my_long_variable_name;` | Snake_case is not idiomatic in C# (though it's legal). It looks like Python. | `string myLongVariableName;` (camelCase) |
| `int @class;` | Using `@` to escape a keyword is allowed, but it creates confusion. | `int courseId;` or `int classId;` (avoid `class` entirely). |
| `string _Name;` | Mixing underscores with PascalCase looks sloppy. | `string _name;` (standard private field) or `string Name;` (if it's a public property). |
